# Contributing

Start with a minimal fixture or a precise report of an observed divergence. Include the exact revision, backend, precision, trajectory and seed if relevant, but do not attach private prompts, model weights, secrets or raw machine logs. Keep semantic claims and performance changes separate. For every bug fix, include a test that would fail without the fix.

Run the offline suite and source verifier before opening a change. Research snapshots are byte-exact; patch experimental runners separately from archival imports. Check redistribution rights with the maintainer before importing external material. Public contributions open only after the release gates are cleared.
